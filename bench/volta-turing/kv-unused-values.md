# Unconsumed KV value reads in streamed CUDA resolution

2026-10-24 source and RTX 2060 SUPER check for TODO 7.4. [1Cat-vLLM PR #1204](https://github.com/1CatAI/1Cat-vLLM/pull/1204) skips host value materialization in its direct resolver when a value cannot be installed. Strata has a different division of work: `resolve_kernel` updates a page-to-slot map, and `copy_kernel` (or opt-in `copy_runs_kernel`) moves only the blocks that received slots. The device-side `m.ctl[2]` is the **placed** count. A hit produces no copy task. A block without a slot is left with page-table value `-1`; the attention chunk masks that row before any K or V load. The regular decode value loops also skip a masked row. The K8V4 prompt kernel guards its V loads with a valid row.

The parity harness now installs page zero, then resolves the same selection with every host K/V pointer set to inaccessible address 1. Both the default and split-run K8V4 copy paths pass, and targeted CUDA memcheck reports zero errors for each. FP16, INT8 and Q4 also pass the hit-only check under the split-run path. The existing four-format tests still pass bitwise attention, ring restoration, reused host memory and changed-input graph replay.

This proves no authoritative host value read for the tested hit-only path. The source also limits the copy loop to placed misses, but an overflow request violating the production slot-capacity contract was not exercised. It would need separate safe-capacity handling before being treated as a supported fallback. A valid selected row with zero softmax weight may still have its V fetched by attention; skipping that would be a different numerical and performance experiment requiring real weight-frequency evidence. The upstream direct-resolver change does not map to a new safe Strata copy optimization, so no production setting changes here.
