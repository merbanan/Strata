# Bounded KV history staging: implementation boundary

2026-10-24, source audit only. The model stayed unloaded to preserve host RAM. TODO 8.3 remains open.

The streamed target prefill path allocates one K/V staging pool for every logical page of a QSA layer (`take_stage`, `src/prefill/prefill.cpp`). Before attention, `kv_stage_from_host` copies the layer's entire prior prefix `[0, p0)` into that identity-mapped pool. The chunk's new rows are also appended there. The prompt attention kernels read selected cell IDs through that page table and return normalized FP32 outputs. K8V4 stays encoded in the staging pool and is dequantized at gather; the draft's own state is INT8 in its window-sized ring.

A smaller staging pool cannot simply reuse the current identity page table: selected pages outside the pool would point past it. A page-window implementation needs a remapped table or selected-ID translation, copy/compute fences before reusing each window, and an attention partial for every selection slice. The current prompt attention API returns only the normalized result. Correctly combining slices needs each partial's maximum score, exponential sum (or log-sum-exp), and weighted value sum. Averaging normalized outputs or merging them with slice lengths changes attention. The merge must also handle empty slices, the last partial page, selections crossing a page boundary, query-dependent widths, and a window that ends exactly at the draft's attention cutoff.

The first implementation gate is a test-only partial-attention API plus a GPU parity harness that compares the merged result with unsliced attention for FP16 draft and encoded K8V4 target pools, including those boundaries. The second gate is a bounded staging planner with an explicit VRAM cap and exact page remapping. Only then can a whole-model ABBA compare output quality, prefill/decode speed, PCIe bytes and expert slots against the current full-prefix staging. The existing stage and dispatch remain in place.
